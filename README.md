# AAM Replication — Arguments that Alter Minds

Palta et al. (2026), in "Arguments that Alter Minds: LLM Rationales Sway Human (and LLM) Notions of Plausibility," show that LLM-generated rationales systematically shift how both humans and LLMs rate the plausibility of answer choices. We replicate this LLM-only effect on a subset of the original data, then test whether it generalizes to cybersecurity attribution — a domain where genuine ambiguity (multiple APT groups share similar TTPs) may make LLMs more susceptible to confident-sounding rationales.

**Paper:** Palta, Rankel, Wiegreffe & Rudinger (ACL 2026)
**Original dataset/code:** https://github.com/shramay-palta/AAM

## Part 1: AAM Replication (SIQA + CQA)

Replicates the LLM-rater experiments from the paper using SIQA (social commonsense) and CQA (causal commonsense) questions.

### Pipeline

1. **Rationale generation** (temp=1) — for each `(question, choice)` pair, generate a PRO rationale (arguing for plausibility) and a CON rationale (arguing against).
   - Prompts A.1–A.2 from paper Appendix A.5
   - *Skipped when using `data/prepared.csv` — rationales are pre-generated by GPT-4o from the paper*
2. **Plausibility rating** (temp=0.1 for non-OpenAI models) — rate each pair under 4 conditions: NO rationale, PRO only, CON only, PRO+CON. 1–5 Likert scale (Impossible → Very Likely).
   - Prompts A.3–A.6
3. **Analysis** — Δ from NO baseline, chi-squared tests of homogeneity, OLS regression for anchoring effects.

### Key findings to replicate (from paper)

- PRO rationales raise distractor ratings but *drop* gold label ratings
- CON rationales drop both, but drop gold more sharply (>1 Likert point avg)
- PRO+CON ≈ average of PRO and CON effects
- Higher initial NO rating → smaller subsequent change (anchoring)

### Usage

```bash
# Prepare data from the AAM repo (run once — requires cloning https://github.com/shramay-palta/AAM)
python prepare_data.py --aam-dir "/path/to/AAM" --output data/prepared.csv

# Fast test run (10 questions, skip rationale gen)
python run_pipeline.py --model qwen3:32b --input data/prepared_test.csv --skip-rationale-gen

# Full replication
python run_pipeline.py --model qwen3.6:35b gemma4:31b deepseek-r1:32b \
    --input data/prepared.csv --skip-rationale-gen

# List available local models
python run_pipeline.py --list-models
```

Output CSVs → `results/` with columns: `question, choice, condition, rating, rating_raw, model, answer_label, dataset`

## Part 2: Cybersecurity Extension (APT Attribution)

Tests whether the AAM rationale-sway effect holds in APT threat attribution — a domain where:
- Multiple actors share overlapping TTPs and targeting patterns
- Attribution is inherently uncertain even for human analysts
- LLMs may be particularly susceptible to confident-sounding rationales

### Dataset design

**Source:** TRACER project — labeled CTI reports from `cti_bm25_dataset_cybercriminal.csv` (957 reports, labeled by MITRE G-code via alias matching).

**8 actors selected** (all have ≥25 labeled reports across sources):

| G-code | Actor | Reports (after QC) | Nation-state nexus |
|--------|-------|-------------------|--------------------|
| G0007  | APT28 | 56 | Russia |
| G0010  | Turla | 36 | Russia |
| G0016  | APT29 | 17 | Russia |
| G0032  | Lazarus Group | 44 | North Korea |
| G0034  | Sandworm | 22 | Russia |
| G0045  | menuPass | 21 | China |
| G0046  | FIN7 | 7 | Criminal |
| G0049  | APT34 | 16 | Iran |

**Question format:** Each question is a de-identified threat report summary containing: behavioral narrative (actor/malware redacted), ATT&CK technique IDs, tactic categories, targeted sectors, delivery vectors, and observed tools.

**Choice format:** An APT group name (e.g. "APT28", "Turla"). Each report generates exactly 2 rows — one gold, one distractor.

**Distractor selection rationale:**
- Russian actors (APT28, Turla, APT29, Sandworm) use each other as distractors — same nation-state nexus creates genuine plausibility ambiguity
- Lazarus, menuPass, APT34, FIN7 (single-actor nexus) use highest TTP-Jaccard wrong actor as distractor
- Rationale: real attribution ambiguity occurs within nexus groups; same-nexus distractors are genuinely confusable, paralleling AAM's wrong-but-plausible commonsense answer choices

**Scrubbing applied to question text:**
- Hashes (MD5/SHA1/SHA256), IP addresses, hex values → `[HASH]`, `[IP]`, `[HEX]`
- Defanged domains (e.g. `evil[.]com`) and URLs → `[DOMAIN]`/`[URL]`
- Actor-linked malware names (e.g. Zebrocy→APT28, BlackEnergy→Sandworm, Hidden Cobra→Lazarus) → `[REDACTED_MALWARE]`
- Quality filter: α-character ratio ≥ 55%, ≤ 3 remaining IOC tokens, narrative length ≥ 80 chars

**Final dataset:** `data/cyber_pairs.csv` — 219 reports × 2 = **438 rows**

### Plausibility question framing

> "Given the following threat intelligence report, how plausible is it that **[actor]** conducted this campaign?"

Ratings: 1 (Very Implausible) → 5 (Very Plausible)

Rationale generation:
- PRO: "Argue that [actor] plausibly conducted this campaign, based on the report."
- CON: "Argue that [actor] did NOT conduct this campaign, based on the report."

## Implementation notes

- Rating parser extracts first integer 1–5 from raw model output
- `max_tokens=50` set for rating calls to prevent verbose output
- Output schema: `question, choice, condition, rating, rating_raw, model, answer_label, dataset`
- Always track `answer_label` (gold vs. distractor) — effect direction differs between them
